## Current State

The scvi-tools ResolVI graph dataloader work has been ported into this `scviva-tools` checkout.
SCVIVA graph dataloader integration is complete. A semisupervised kwargs regression was fixed.
Test suites for SCVIVA, DestVI, and GIMVI have been expanded to match scvi-tools upstream coverage.

Implemented behavior:

- `scviva.dataloaders.GraphDataLoader` yields `torch_geometric.data.Data` batches.
- `scviva.dataloaders.GraphDataSplitter` returns graph train/validation/test dataloaders.
- `GraphDataSplitter` accepts `n_samples_per_label` and applies label-resampling at index
  level, preventing `TypeError` from semisupervised kwargs reaching `AnnDataLoader`.
- `scviva.model.ResolVI` defaults to `GraphDataSplitter`.
- `ResolVI.train()` supports graph-scoped neighbor expression cache settings:
  - `cache_neighbor_expression: bool | Literal["auto"] = "auto"`
  - `neighbor_expression_cache_max_bytes: int | None = 1_000_000_000`
- In graph cache mode, `datasplitter_kwargs["load_neighbor_expression"]` defaults to `False`.
- `RESOLVAEModel._get_fn_args_from_batch()` supports three paths:
  1. model-side cache gather from `index_neighbor`;
  2. prefetched graph batch `x_n`;
  3. legacy `AnnTorchDataset` fallback.
- `scviva.model.SCVIVA` defaults to `GraphDataSplitter`.
- `SCVIVA.train()` maps the splitter to the registered `niche_indexes`/`niche_distances`
  fields and disables unused raw neighbor expression prefetch.

## Known Caveats

- `torch-geometric` is optional, but `ResolVI` and `SCVIVA` default to graph dataloading.
  Training without PyG installed fails with the `GraphDataLoader` install hint.
- Cross-split neighbor expression is intentional and matches upstream ResolVI.
- The dense neighbor expression cache is a plain runtime attribute; not saved in checkpoints.
- `logger=False` in `model.train()` disables history recording — do not use it in tests that
  check `model.history["elbo_train"]`.
- `_make_spatial_adata()` neighbor index uses `(i + j + 1) % n_cells` (not `if j != 0` filter)
  to guarantee exactly `n_neighbors` entries matching `distances` shape — the filter version
  produced shape `[n, n_neighbors-1]` causing `GraphBatchConverter` reshape mismatch.
- GraphDataLoader `edge_obsm_keys` defaults to `["distance_neighbor"]`; the legacy path
  (`DataSplitter`) must NOT receive `datasplitter_kwargs` containing graph-specific keys
  (`neighbor_indices_key`) — use `_train_graph` / `_train_legacy` split helpers.
- `logger=False` in `model.train()` has no effect on NaN suppression; the real cause of NaN
  in SCVIVA training is empty cells (all-zero counts → `log(0)` in the encoder). Always filter
  with `adata[cell_counts > 0].copy()` before calling `setup_anndata` in tests.
- `synthetic_iid` with `n_genes=20` and any `dropout_ratio` reliably produces empty cells.
  The `_prepare_scviva_adata` fixture in `test_scviva_graph_dataloader.py` now filters them.
- SCVIVA GraphDataLoader speed ratio vs AnnDataLoader can exceed 3× locally due to niche-
  composition field processing; the speed-comparison test uses a 10× threshold.
- `predict_niche_activation()` last dim is `n_latent_intrinsic` (from `X_scVI` embedding),
  not `model.module.n_latent` (SCVIVA latent dim).
- `@pytest.mark.optional` tests (scarches, DE) and `@pytest.mark.benchmark` tests are
  deselected by default; run explicitly with `-m optional` or `-m benchmark`.
