## Known Caveats

- `torch-geometric` is optional, but `ResolVI` and `SCVIVA` default to graph dataloading.
  Training without PyG installed fails with the `GraphDataLoader` install hint.
- Cross-split neighbor expression is intentional and matches upstream ResolVI.
- The dense neighbor expression cache is a plain runtime attribute; not saved in checkpoints.
- `logger=False` in `model.train()` disables history recording — do not use it in tests that
  check `model.history["elbo_train"]`.
- `_make_spatial_adata()` neighbor index uses `(i + j + 1) % n_cells` (not `if j != 0` filter)
  to guarantee exactly `n_neighbors` entries matching `distances` shape — the filter version
  produced shape `[n, n_neighbors-1]` causing `GraphBatchConverter` reshape mismatch.
- GraphDataLoader `edge_obsm_keys` defaults to `["distance_neighbor"]`; the legacy path
  (`DataSplitter`) must NOT receive `datasplitter_kwargs` containing graph-specific keys
  (`neighbor_indices_key`) — use `_train_graph` / `_train_legacy` split helpers.
- `logger=False` in `model.train()` has no effect on NaN suppression; the real cause of NaN
  in SCVIVA training is empty cells (all-zero counts → `log(0)` in the encoder). Always filter
  with `adata[cell_counts > 0].copy()` before calling `setup_anndata` in tests.
- `synthetic_iid` with `n_genes=20` and any `dropout_ratio` reliably produces empty cells.
  The `_prepare_scviva_adata` fixture in `test_scviva_graph_dataloader.py` now filters them.
- SCVIVA GraphDataLoader speed ratio vs AnnDataLoader can exceed 3× locally due to niche-
  composition field processing; the speed-comparison test uses a 10× threshold.
- `predict_niche_activation()` last dim is `n_latent_intrinsic` (from `X_scVI` embedding),
  not `model.module.n_latent` (SCVIVA latent dim).
- `@pytest.mark.optional` tests (scarches, DE) and `@pytest.mark.benchmark` tests are
  deselected by default; run explicitly with `-m optional` or `-m benchmark`.
- Tutorial notebooks were syntax-checked but not executed end to end in this session because they
  download external data and run long tutorial training.
- Tutorial metric sections now use `scib_rapids` metric functions directly. The installed
  `scib-rapids` package does not expose a `benchmark.Benchmarker` module.
- The new spatial metric groups (`CoordinatePreservation`, `NichePreservation`, `DomainBoundary`)
  are not available in `scib_rapids` yet, so tutorials report RAPIDS-backed bio/batch metrics
  only. The optional `tests/regression/test_scib_metrics_spatial.py` file still covers those
  spatial classes through `scib_metrics` for environments where that separate spatial API is needed.
- `BRAS`, `iLISI`, `KBET`, and `PCR comparison` require enough batch structure; tutorial helper
  leaves those columns as `NaN` where the dataset has only one batch or no multi-batch labels.
- ResolVI uses Pyro's global param store. Do not train a second ResolVI model before calling DE,
  posterior sampling, or query-transfer methods on `supervised_resolvi`; the AnnDataLoader
  comparison is intentionally at the end of the tutorial for this reason.

## Investigation: Why GraphDataLoader shows no difference vs AnnDataLoader in SCVIVA

**Trigger**: Tutorial `scVIVA_tutorial_scib_spatial_scores_new.ipynb` compares 5 models
(PCA, SCANVI, SCVIVA-legacy, SCVIVA-anndl, SCVIVA-graphdl). Loss curves and scib-metrics
spatial scores are identical for all 3 SCVIVA variants despite expecting graph DL to differ.

### Root Cause — CONFIRMED

**`nicheVAE.loss()` (`src/scviva/module/_nichevae.py:508`) reads ONLY precomputed obsm fields:**

```python
niche_weights = tensors[SCVIVA_REGISTRY_KEYS.NICHE_COMPOSITION_KEY]   # precomputed alpha
z1_mean_niche = tensors[SCVIVA_REGISTRY_KEYS.Z1_MEAN_CT_KEY]          # precomputed eta
```

GraphDataLoader adds to each batch: `edge_index`, `edge_attr`, `x_n` — **all completely ignored**.
Neither the loss nor the encoder/decoders read these fields.

Additionally, `SCVIVA.train()` (`src/scviva/model/_scviva.py:249`) explicitly disables neighbor
expression loading:

```python
datasplitter_kwargs.setdefault("load_neighbor_expression", False)
```

So `x_n` is never even populated in the batch.

### Consequence Chain

1. GraphDataLoader produces PyG `Data` objects with graph structure → model ignores them
2. Both AnnDL and GraphDL feed identical precomputed alpha/eta to the same loss
3. Training is identical → same latent representations
4. Same latent → identical scib-metrics scores (including spatial metrics)
5. Loss curves look the same because they ARE the same computation

### What Needs to Change (Options)

**Option A — Dynamic eta computation (high impact, high cost)**
Replace static `Z1_MEAN_CT_KEY` with live aggregation over neighbor latents during forward.
Requires encoder to run on neighbor expression (x_n), aggregate by cell type, compute eta per batch.
Would require `load_neighbor_expression=True` and changes to `nicheVAE.inference()` or `generative()`.

**Option B — GNN message passing (most architecturally correct)**
Add GNN layers to encoder using `edge_index`. Would make spatial structure explicitly part of the
learned representation.

**Option C — Accept current state, document clearly**
GraphDataLoader is currently a "future extension point" — provides graph structure in batches
for future GNN layers, but current nicheVAE doesn't use it. Scores will always be identical.
Update tutorial to make this explicit.

We will implement both (A+B)

### Tests

Tests **do not** catch this because:
- `test_scviva_elbo_comparable_between_paths` asserts ELBOs are *similar*, not *different*
- `test_graph_vs_ann_spatial_quality.py` is for ResolVI and explicitly notes "identical training signal"
- No test asserts graph path produces *better* spatial metrics than ann path

To actually validate Option A/B, a test would need to assert `spatial_nnp(graph) > spatial_nnp(ann) + threshold`.

## 2026-05-14 Codex continuation update

### Implemented after Claude handoff

- `GraphDataLoader` / `GraphDataSplitter` now support:
  - `load_neighbor_labels=True`, yielding flattened neighbor labels as `y_n`.
  - `neighbor_obsm_keys={output_key: registry_key}`, yielding flattened neighbor obsm tensors
    such as `z1_n` from `SCVIVA_REGISTRY_KEYS.Z1_MEAN_KEY`.
- `SCVIVA.train()` now enables neighbor expression, neighbor labels, and neighbor registered
  embeddings when `module.use_graph_encoder` is true.
- `nicheVAE` now consumes graph batch tensors:
  - `x_n` is encoded into neighbor latent vectors.
  - `edge_index` maps flattened neighbor slots back to center cells.
  - `edge_attr` distance is used as an attention penalty.
  - `z_spatial` is an edge-index-based attention/message-passing aggregate added to the
    niche decoder input.
  - `dynamic_eta` replaces static `Z1_MEAN_CT_KEY` in the niche-expression loss when available.

### Important correction to Claude implementation

Claude's first dynamic-eta implementation aggregated neighbor model latents (`z_n_flat`), which
has shape `[batch * K, module.n_latent]`. That only works accidentally when the registered SCVIVA
embedding dimension equals `module.n_latent`.

Real SCVIVA tests often use `X_scVI` / `Z1_MEAN_KEY` with a different dimension, e.g. 20, while
`module.n_latent` is 10. This caused:

```text
ValueError: Value is not broadcastable with batch_shape+event_shape:
torch.Size([128, 3, 10]) vs torch.Size([128, 3, 20])
```

Fix: dynamic eta now aggregates neighbor `Z1_MEAN_KEY` embeddings (`z1_n`) by neighbor label, so
its final dimension matches the registered niche activation target used by the decoder/loss.
